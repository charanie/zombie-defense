## 公式（与 `src/data/balance.js` 一致）

```
僵尸数量 N = 6 + 5R
僵尸 HP = 基础 × 1.07^(R-1)
僵尸伤害 = 基础 × 1.01^(R-1)，上限 +50%
僵尸速度 = 基础 × min(1.25, 1 + 0.005(R-1))
击杀金 = floor(基础 × (1 + 0.03(R-1)) × 科技击杀倍率)
通关奖励 = floor((60 + 12R) × 科技奖励倍率)
BOSS HP = 1200 × 1.15^(R-1)
BOSS 石块 = 80 + 6R
BOSS 奖励 = 400 + 50R
人口上限 = min(80, 8 + 2R)
感染 DPS = 最大生命 × 0.0002 × 感染值
科技节点价格 = round(层级基础价 × 1.35^(等级))
层级基础价 = [120, 200, 300, 420, 580, 800]
存款加伤 = min(上限, floor(金钱 / 500) × 0.02)
援助轰炸伤害 = 300 + 12R
尸爆伤害 = 80 + 8R
```

## 性能基准

### Node（`node tests/bench.js`）

```
entities: 300 zombies, 99 humans, 100 projectiles
steps=600
avgStepMs≈1.39  maxStepMs≈14
```

v1.2 的小队每步更新、动态流场重建与四面出生带来额外开销；为守住 2.5ms 预算做了以下优化（行为不变或近似不变）：

- `Stats.range`：高频索敌只算射程，不构造完整属性对象。
- 索敌每次只算一次距离；霰弹/喷火/火箭的密度评估只看最近 24 个目标。
- 目标缓存 1 步（同一模拟步内复用，避免重复空间查询）。
- 人类/僵尸分离先用平方距离比较，避免无谓开方。
- 盾尸 vanguard 预计算最近人类距离，避免 O(僵尸²)。

### 浏览器

v1.1 记录（Canvas 1269×714，DPR 1，headless Chromium）：`Sim.step` 1.70ms、渲染+HUD 4.65ms。v1.2 需在 Task 12 浏览器 QA 中复测。

### 调参入口

- 整体难度：`balance.js` 的 `1.06` 与 `6+5R`（v1.2 未改）。
- 小队：`data/humans.js` 的 `humanAi.squad`。
- 盾尸：`data/zombies.js` 的 vanguard / intercept 参数。
- 兵种：`data/humans.js`；建筑：`data/buildings.js`；出怪节奏：`constants.js` 与 `waves.js`。
- bot 策略：`tests/policy.js`（站位环、兵种目标、后期升级）。

## 已知平衡观察

- 四面来袭后，单一小队会被多方向拉扯；分散放置多名盾兵形成多小队是 R10+ 的关键。
- 盾尸正面拦截让纯机枪/手枪阵容在 R4+ 明显吃力；喷火（不被拦截、对盾 2 倍）与侧翼是解法。
- R35（第 5 个 BOSS）是混合 bot 的主要墙；R40 通关级仍可达到。
- 金钱在 R20 后增长快于人口上限支出，bot 用“卖手枪/平民 → 补机枪/火焰”消耗。
