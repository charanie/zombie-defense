# 尸潮防线 v1.3 详细实现方案

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) 或 superpowers:executing-plans，按任务逐项执行。步骤使用 checkbox（`- [ ]`）跟踪。

**Goal:** 把 v1.2 的「单只 BOSS 坦克 + 固定投石节奏」改造成 v1.3 的「四只机制型 BOSS 池 + 轮换不重复 + 数据驱动参数」：坦克投石降频，新增裂爪（冲刺刺客）、腐吐者（三弹炮台）、母巢（召唤/光环），并补齐毒伤管线、BOSS 通用死亡/奖励、像素精灵与测试。

**Architecture:** 保持 1280×720 固定世界、`1/60` 固定步长、零依赖经典脚本、`globalThis.ZG` 命名空间。**不新增运行时 JS 文件**：四只 BOSS 全部由 `src/data/zombies.js` 的数据驱动，`src/sim/ai.js` 按 `boss.kind` 分派四个处理函数；投射物、毒伤、光环分别在 `projectiles.js`、`infection.js`、`stats.js` 内扩展。BOSS 类型选择走独立随机流 `state.rng.boss`，BOSS 技能随机走独立 `state.rng.skill`，不扰动既有 `spawn` 流的出生布局。

**Tech Stack:** 原生 JavaScript（ES5 风格 IIFE）、Canvas 2D、DOM HUD、CSS、Node 内置测试（`node --test`）、无 npm 运行时依赖、无构建步骤。

**Spec:** `docs/superpowers/plans/2026-10-21-v1.3-boss-system-design.md`（下称「源计划」，即用户提供的 v1.3.0 BOSS 体系改造计划书）。

**文档关系与冲突裁决：** 本文件是源计划的实现级伴随文档。冲突时按以下优先级：用户已确认决策 → 本方案 §1.2「源计划校正」 → 源计划其余部分 → 现有代码。本方案不改变源计划 §八「明确不做」的非目标。

## Global Constraints

以下约束来自 `AGENTS.md`，每个任务都隐含适用：

- **运行时零依赖、零构建**：不引入 npm 包、打包器、ES module、外部字体/图片/音频。所有资源本地静态。
- **`file://` 必须可玩**：不能用 ES module / `fetch` 加载游戏代码 / Service Worker 作为必需路径。
- **加载顺序唯一真相**：所有脚本只在 `index.html` 中按顺序声明；测试用 `tests/load-sim.js` 解析它。**本改造不新增运行时文件**，所以 `index.html` 的 `<script>` 列表与 `sw.js` 的 `SHELL` 列表都不加文件，只改 `sw.js` 的缓存名。唯一新增文件是 `tests/boss.test.js`。
- **分层**：`src/core` ← `src/data` ← `src/sim` ← `src/view` / `src/main.js`。`src/sim/**`、`src/data/**`、`src/core/**` 不得访问 `document`、`window`、`localStorage`、`Math.random()`、`Date.now()`、`performance.now()`。
- **确定性**：模拟随机一律走 `state.rng.*`；同种子 + 同整备期命令必须得到相同 `ZG.State.hash()`。目标选择排序必须显式指定 `id` 决胜，不得依赖对象遍历顺序。
- **固定步长**：`ZG.Const.STEP_SEC = 1/60`，不得用帧数当时间。
- **数值集中**：单位/僵尸/英雄/建筑/地图/波次/公式只写在 `src/data/**`；`src/sim/**` 不写魔法数字。本计划新增参数全部进入 `src/data/zombies.js`、`src/data/balance.js`、`src/core/constants.js`。
- **中文文案**：所有玩家可见文字为简体中文；代码标识符用英文。
- **可访问性**：颜色之外有符号/文字/形状；伤害数字与震屏可关；暂停随时可用。
- **每个任务结束必须 `npm test` 全绿**；最终必须运行 `node tests/bench.js`、`node tests/bot.js --rounds 40 --seed 1`，并完成浏览器手验后才能声称完成。

## Review Focus

以下六类问题最容易「看起来能跑但实际不能玩」。每一条都必须在对应任务里有测试或明确验收步骤：

1. **裂爪伤害被二次清零**：`state.js` 在 209/212 行把 BOSS 的 `damage` / `damageBase` 置 0，243 行又清一次。`Stats.zombie` 优先读 `z.damage`，只改 243 行不够；必须同时写入 `z.damage = z.damageBase = bossSkillDamage(...)`，并把 243 行改成仅对无 `melee` 的 BOSS 生效。
2. **BOSS 池选择的确定性**：BOSS 类型必须用独立的 `state.rng.boss`；若复用 `state.rng.spawn`，会改变洗牌与出生点序列，直接打破 v1.2 的 bot 基线与回放。技能随机用独立的 `state.rng.skill`，不污染 `jitter`（人类攻击散布）与 `spawn`（母体爆仔/波次）。
3. **腐吐者子弹永远打不到人**：`projectiles.js:154-158` 的通用抵达分支写死 `hitsHumans:false`。腐吐弹必须走独立的 `impactSpit`，且所有通用投射物都要透传 `p.hitsHumans / p.hitsBuildings / p.infection / p.ignoreShield`。
4. **裂爪冲刺的穿透与穿墙**：750px/s × 1/60 ≈ 12.5px/步，单步点判定通常不会漏，但低帧/卡顿/减速下仍可能穿人。用「上一位置 → 当前位置」的 `Geom.segmentCircleT` 扫掠；冲刺移动仍走 `moveZombie`，不直接改坐标，保证不穿墙。
5. **母巢光环与幼体上限**：光环必须每 tick 先全体重置为 1，再按存活母巢覆盖；幼体预算不能与母体共用累计 `babyCount`，否则母巢约 75 秒耗尽 30 的预算，同一回合母体爆不出仔。
6. **旧测试与 bot 回归**：R7 首只 BOSS 随机化后，`tests/acceptance.test.js` 的 `heroes > 0` 可能因 bot 被裂爪冲穿后排而挂。**不得放宽断言**；按 §7 的调参顺序处理。

### 1.2 源计划校正（实现时必须遵守）

以下 13 条是「照抄源计划伪代码会出问题」的地方。每一条都在对应任务里有落点：

1. **`state.js:209/212/243` 三处清零**：源计划只提示 243 行。实际 209 行的 `damage: isBoss ? 0 : data.damage` 与 212 行的 `damageBase: isBoss ? 0 : data.damage` 也会把裂爪伤害置 0。实现时统一用 `bossDamageOf(data, R)` 计算，243 行改为 `if (isBoss && !(data.boss && data.boss.melee)) { z.damage = 0; z.damageBase = 0; }`，并保证 `Stats.zombie` 读到的是近战伤害。
2. **BOSS 判定必须读数据**：`const isBoss = !!(data.isBoss || e.isBoss || typeId === 'boss');`。否则新 BOSS 会吃普通僵尸的 `1.06/1.01` 成长、没有 `bossId`、没有技能计时器。
3. **`Waves.preview` 不抽 RNG**：整备期 `Spawner.prepare` 尚未执行，无法知道本回合 BOSS 类型；预览只显示「随机 BOSS」。不要在 `preview`/`Model.wavePreview` 里消费任何随机流。
4. **投射物抵达分支透传**：`projectiles.js:154-158` 除了 `hitsHumans`，还要透传 `hitsBuildings`、`infection`、`ignoreShield`；腐吐弹在抵达前走独立的 `impactSpit`，不经过 `explode` 的通用人类分支。
5. **`explode` 人类直击/溅射**：只在 `o.splashMul !== undefined` 时启用「直击 100% / 其余 splashMul」；现有爆尸、母体、队长、石块都没有传 `splashMul`，行为必须保持不变。直击目标不在半径内时回退到半径内最近人类。
6. **腐吐者目标死亡**：源计划伪代码在 `fireSpit` 发现目标已死时 `spitCd = interval`，会空等 2.2 秒。实现裁决：开火瞬间重新索敌（`nearestHuman(..., range + 60)`）；仍无目标则以当前朝向前方 120px 为落点空枪，`spitCd = interval`。普通弹只认 `targetId`，空枪不转伤他人。
7. **裂爪冲刺扫掠**：用 `Geom.segmentCircleT(prevX, prevY, z.x, z.y, h.x, h.y, z.radius + h.radius + dash.hitRadius)`，并保留终点距离判定（处理零位移）。遍历 `state.humans.slice()`，防止击杀后 `splice` 跳人；`dashHitIds` 保证每个目标只吃一次。冲刺仍走 `moveZombie`，不直接改坐标。
8. **幼体预算分离**：源计划伪代码让母巢与母体共用累计 `babyCount`，母巢 5s × 2 只约 75 秒耗尽 30，同一回合母体将爆不出仔。实现裁决：
   - 母体：保留现有累计 `state.battle.babyCount` 与 `waveCap: 30`，代码不动。
   - 母巢：`summonedBy === z.id` 的存活幼体 ≤ `maxAlive: 8`；全场存活幼体 ≤ 30；`state.zombies.length < Spawner.zombieCap(state)`；**不写** `babyCount`。
9. **腐吐弹落点**：源计划 `impactSpit` 用 `p.x/p.y`，到达时还没走到 `tx/ty`；统一用 `p.tx/p.ty`。毒云 effect 也用 `tx/ty`。
10. **RNG 隔离强化**：除源计划的 `state.rng.boss` 外，本方案增加 `state.rng.skill`，专用于 BOSS 技能随机（腐吐弹种、母巢落点）。理由：源计划用 `jitter` 抽弹种会与人类攻击散布耦合，用 `spawn` 抽召唤落点会改变母体爆仔/后续出生序列。若必须严格照源计划，至少把召唤落点从 `spawn` 移到 `skill`。

### 3.3 `src/data/balance.js`

```js
  function bossHp(R, hpMul) {
    const mul = hpMul === undefined ? 1 : hpMul;
    return 1200 * pow(1.14, R - 1) * mul;
  }
  function bossSkillDamage(base, growth, R) {
    return base + growth * R;
  }
  function bossRockDamage(R) {
    return bossSkillDamage(80, 6, R);
  }
  function bossPrimaryDamage(typeId, R) {
    const data = (ZG.Data.zombies && ZG.Data.zombies[typeId]) || null;
    const bd = data && data.boss;
    if (!bd) return bossRockDamage(R);
    if (bd.kind === 'tank' && bd.rock) {
      return bossSkillDamage(bd.rock.damageBase, bd.rock.damageGrowth, R);
    }
    if (bd.kind === 'ripper') {
      const m = bd.melee ? bossSkillDamage(bd.melee.damageBase, bd.melee.damageGrowth, R) : 0;
      const d = bd.dash ? bossSkillDamage(bd.dash.damageBase, bd.dash.damageGrowth, R) : 0;
      return Math.max(m, d);
    }
    if (bd.kind === 'spitter') {
      const ex = (bd.bullets || []).find(b => b.id === 'explosive');
      return ex ? bossSkillDamage(ex.damageBase, ex.damageGrowth, R) : 0;
    }
    return 0; // brood：本体无伤害
  }
```

    if (z.spitCd > 0) z.spitCd -= dt;

    if (z.spitWindupT > 0) {
      z.spitWindupT -= dt;
      if (z.spitWindupT <= 0) fireSpit(state, z, bd);
      return;
    }

    const t = nearestHuman(state, z.x, z.y, bd.range + 60);
    if (!t) {
      const p = densestHumanPoint(state);
      moveZombie(state, z, p.x, p.y, speed, dt);
      return;
    }

    z.facing = Math.atan2(t.y - z.y, t.x - z.x);
    const dist = ZG.Geom.dist(z.x, z.y, t.x, t.y);
    const intent = spitterIntent(dist, bd);
    if (intent === 'retreat') {
      const a = Math.atan2(z.y - t.y, z.x - t.x);
      moveZombie(state, z, z.x + Math.cos(a) * 200, z.y + Math.sin(a) * 200, speed, dt);
    } else if (intent === 'approach') {
      moveZombie(state, z, t.x, t.y, speed, dt);
    }

    if (z.spitCd <= 0 && dist <= bd.range) {
      z.spitWindupT = bd.windup;
      z.spitTargetId = t.id;
      z.nextBullet = pickSpitKind(bd.bullets, state.rng.skill.next());
    }
  }

  function fireSpit(state, z, bd) {
    const k = z.nextBullet;
    z.nextBullet = null;
    if (!k) { z.spitCd = bd.interval; return; }

    let t = state.humans.find(h => h.alive && h.id === z.spitTargetId);
    if (!t) t = nearestHuman(state, z.x, z.y, bd.range + 60);

    let tx, ty;
    if (t) {
      const lead = bd.leadMax || 0;
      tx = t.x + (t.moveX || 0) * lead;
      ty = t.y + (t.moveY || 0) * lead;
    } else {
      tx = z.x + Math.cos(z.facing) * 120;
      ty = z.y + Math.sin(z.facing) * 120;
    }

    const poison = k.dot ? {
      dps: ZG.Balance.bossSkillDamage(k.dot.dpsBase, k.dot.dpsGrowth, state.round),
      duration: k.dot.duration
    } : null;

    ZG.Projectiles.spawn(state, {
      typeId: 'spit', spitKind: k.id,
      x: z.x, y: z.y, tx, ty,
      targetId: t ? t.id : 0,
      speed: k.speed, life: k.life || 4,
      radius: k.radius, splash: k.splash,
      damage: ZG.Balance.bossSkillDamage(k.damageBase, k.damageGrowth, state.round),
      splashMul: k.splashMul,
      poison,
      damageKind: k.id === 'poison' ? ZG.Const.DAMAGE.POISON : ZG.Const.DAMAGE.RANGED,
      hitsHumans: true,
      ignoreShield: k.id === 'poison',
      ownerId: z.id,
      color: k.color
    });
    z.spitCd = bd.interval;
    state.bus.emit('fx:spit', { x: z.x, y: z.y, kind: k.id, color: k.color });
  }

### 6.3 性能预算

- 预算：`avgStepMs ≤ 2.5`，`maxStepMs ≤ 30`（Node bench）。

### 7.2 调参顺序

**裂爪秒后排（bot 多 seed）**

1. `dash.damageBase 85 → 70` 或 `damageGrowth 7 → 5`（R7 134 → 105/120）。
2. `dash.cooldown 5 → 6.5`。
3. `dash.windup 0.45 → 0.6`、`dash.stagger 0.9 → 1.1`。
4. `dash.firstDelay 2.0 → 3.5`。
5. 最后才 `hpMul 0.45 → 0.5`。

**R7 首战过硬**

- 坦克：先 `stomp.damage 80 → 70` 或半径 60 → 54；**不要**回调投石频率（用户反馈就是降频）。
- 腐吐者：先 `dot.dpsBase 9 → 7.5` 或 `duration 3.5 → 3.0`；再毒弹概率 35% → 30%；最后爆炸弹 15% → 10%。
- 母巢：先 `summon.interval 5 → 6` 或 `maxAlive 8 → 6`；再 `aura.damageMul 1.2 → 1.15`；死亡爆仔 3 → 2 最后。
- 太容易死：优先提高 `hpMul`（0.45→0.55 / 0.36→0.42 / 0.60→0.70），不要提高伤害，保持 8–15 秒 TTK。
