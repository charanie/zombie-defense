## Context

当前科技只是底栏里四行线性等级：火力 / 护甲 / 经济 / 血清，每条 0–10 级，没有任何节点、前置或分支结构（`src/core/state.js:25`、`src/data/balance.js:63-80`、`src/view/hud.js:250-264`）。玩家在整备期只能反复点同一行，科技既不像“树”，也没有职业差异；四名英雄的技能强化、各职业的被动/主动能力完全没有成长空间。

本次重做要解决三件事：

1. **把四条线性等级换成真正的节点树**：4 个分支、6 级、47 个节点，同层可多买，上一层任一点解锁下一层。
2. **让科技改变战斗内容而不只是数值**：火力分支给 8 个职业分别加被动 + 主动技能；经济分支加入建筑强化、存款加伤、金钱援助技能；生命分支加入回血、复活、尸爆；英雄分支强化四名英雄的独有机制。
3. **把科技页从小面板变成大窗口**：桌面/应用版 4 列竖向树（低级在上、高级在下，连线连接），手机版分支标签页 + 横向树（低级在左、高级在右）。

最终产出是一份可直接执行的实现计划：数据表、状态结构、效果接入点、UI 规格、测试与验收、分阶段顺序。

### 目标

- 科技树成为**单局内的主要成长决策**：四条分支各有明确流派，钱不够时必须取舍。
- 每个职业的被动/主动都能在战斗中**被看见、被理解**，而不是隐藏数值。
- 科技页在桌面和手机上都能**一屏看懂层级与前置**，不再是一行行等级。
- 保持零依赖、零构建、`file://` 可玩、固定步长与同种子可复现。

### 非目标

- 不做跨局/账号级科技继承，不做成就解锁。
- 不新增第五分支，不重做地图、僵尸、BOSS 数量与英雄获取方式。
- 不把职业主动技能改成玩家手动释放（只有经济援助是手动）。
- 不引入 npm 包、打包器、ES module、外部字体或图片。
- 不修改现有 `zd_settings` / 最高回合存档格式。

### 反目标（出现即视为失败）

- 科技树变成“每层点一个最强的”而无脑路线。
- 手机端必须横屏或反复缩放才能操作科技页。
- 战斗因为援助按钮变成频繁暂停的即时战术游戏。
- 新技能让 300 僵尸基准超出 2.5ms/步，或让回放不再确定。

## 一、已确认的设计决策

| # | 决策点 | 结论 |
|---|---|---|
| 1 | 主动技能释放方式 | **职业主动技由 AI 自动释放**；范围治疗、导弹轰炸由**玩家手动点按钮 + 点地图位置**施放 |
| 2 | 树规模 | **6 级 × 每级 1–4 节点**，四分支共 47 节点 |
| 3 | 同层规则 | **同层节点可全部购买**；买过上一层任意节点即解锁下一层 |
| 4 | 节点等级 | **基础数值节点可多级（最多 5 级）**；技能/解锁节点一次性 |
| 5 | 存款加伤 | 每 500 金 +2% 全体伤害，**上限 +60%**（节点分 3 级提高上限：20%/40%/60%） |
| 6 | 场外援助 | **消耗金币 + 手动选点**；默认各每回合 1 次 |
| 7 | 原血清效果 | **并入英雄分支「医疗体系」**（治疗兵血清/治疗量、医疗站、疫医群疗） |
| 8 | 手机版布局 | **分支标签页切换**；单分支内等级从左到右 |
| 9 | 科技页入口 | **仅整备期可开**；战斗中入口隐藏 |
| 10 | 平衡目标 | **同步提高难度**，自动 bot 仍以 R38–42 为通关线 |
| 11 | 平民 | **只给被动「拾荒」**，不给主动 |
| 12 | 定价 | **层级定价 + 基础节点按级递增** |

### 我在计划中自行裁定、需要你复核的项

| 项 | 裁定 | 理由 |
|---|---|---|

| 复活触发频率 | 每单位每回合最多 1 次 | 防止高概率连续复活拖长战斗 |
| 科技页购买方式 | **先点节点看详情，再点「购买」** | 大窗口内避免误触，手机上尤其重要 |
| 科技树是否跨局保存 | 不保存，单局内永久 | 与现有“单局永久、刷新重置”一致，不改存档结构 |
| 战斗暂停 | 施放援助**不暂停**；科技页只在整备期打开 | 保持战斗节奏 |
| 前置是否跨分支 | **分支内解锁**：火力 T3 只解锁火力 T4 | 四分支独立成长，避免“火力 T1 → 英雄 T6”串线 |
| 队长能否复活 | **不能**；队长仍只走死亡爆炸 | 与“普通人类 = 队长外人类”的表述一致，避免复活+爆炸叠加 |
| 存款加伤作用范围 | **仅人类**（含队长/英雄/转化兵），不含哨塔、建筑、援助伤害 | 防止援助爆发被二次放大 |
| 节点购买次数 | 首级即解锁下一层，不要求满级 | 与已确认的“上一层任一点解锁”一致；跳级速通作为平衡风险监控 |

## 二、科技树总览

### 2.1 分支与节点数

| 分支 | 主题 | 节点数 | 关键内容 |
|---|---|---:|---|
| 火力 | 输出 + 职业能力 | 20 | 伤害/射速基础；8 职业被动 + 主动；3 个终局 |
| 经济 | 金钱 → 战力 | 8 | 收入、建筑生命/数量、存款加伤、范围治疗、导弹轰炸、援助强化 |
| 生命 | 生存与容错 | 8 | 全员生命、每 5 秒回血、概率复活、尸爆、抗感染/减伤、绝境 |
| 英雄 | 四英雄机制强化 | 11 | 英雄攻/血、长官导弹、武士剑气、加特林鼓舞、疫医转化、医疗体系 |

### 2.2 购买规则

- 整备期（`state.status === 'prep'`）才能购买；战斗中科技入口隐藏。
- 节点状态：`锁定`（未满足前置）→ `可购买`（前置已满足、钱够）→ `已购买`（技能节点）/ `已满级`（数值节点）。
- 前置：**同分支上一层任意节点已购买**即可解锁下一层；T1 无前置。
- 多级节点：等级 1–maxRank，逐级购买，效果线性叠加。
- 技能节点：一次性，购买后永久生效（单局）。
- 不可退款。
- 购买立即生效：生命类节点按比例补足现有单位新增生命；建筑生命节点同理。

### 2.3 定价

层级基础价：

| 层级 | T1 | T2 | T3 | T4 | T5 | T6 |
|---|---:|---:|---:|---:|---:|---:|
| 价格 | 120 | 200 | 300 | 420 | 580 | 800 |

多级节点第 n 级价格：`floor(层级基础价 × 1.35^(n-1))`。

示例（T1 五级节点）：120 / 162 / 219 / 295 / 398，满级合计 1,194 金。

全树买满约 3.2 万金，与旧四条 10 级线满级（约 3.5 万）接近；但新树包含大量一次性技能节点，实际单局会按流派取舍，不会全买。

## 四、战斗机制规格

### 4.1 职业主动技能（AI 自动）

- 所有主动技在**开战时冷却清零**，`state.battle.time` 为计时源；每回合重置。
- 触发条件除冷却外，还需满足技能自身条件（有目标、范围内有敌人/友军等）。
- 表现：每个主动技触发时在 `state.effects` 推入对应视觉，并播放现有 `fx:ability` 提示（节流，避免刷屏）。
- BOSS 控制抗性：眩晕类只对普通/精英僵尸生效；BOSS 免疫眩晕，仍受击退以外的伤害。

### 4.2 场外援助（玩家手动）

| 项目 | 范围治疗 | 导弹轰炸 |
|---|---|---|
| 解锁节点 | `support_heal` | `support_bomb` |
| 费用 | 60 金 | 120 金 |
| 每回合次数 | 1（`support_extra` 后 2） | 1（`support_extra` 后 2） |
| 目标 | 地图任意点 | 地图任意点 |
| 效果 | 半径 150 内友军 +120 HP，驱散 40 感染 | 半径 130，伤害 `300+12R`，2 发间隔 0.15s |
| 强化 | `support_power`：半径 +25%、治疗 +25%、费用 -10% | 同左 |

流程：

1. 战斗期底栏出现援助按钮（未解锁则不显示）。
2. 点击按钮进入瞄准模式：`state.ui.pendingSupport = 'areaHeal' | 'missileBombardment'`，画布上跟随指针显示范围圈。
3. 点击地图发出命令；右键 / Esc / 再点按钮取消。
4. 命令校验：战斗期（`not-battle`）、已解锁（`locked`）、次数未用完（`uses`）、金钱足够（`money`）、坐标在地图内（`outside`）。
5. 扣钱、次数 +1、生成效果/投射物；**不暂停**。
6. 按钮显示 `次数 1/1` 与费用；不可用时置灰并给出原因。
7. 轰炸落点使用固定偏移（不用随机），保证同命令回放完全一致；预警圈在落点提前 0.35 秒显示。

### 4.3 确定性

- 新增两个命名 RNG 流（`src/core/rng.js:52-62` 的 `createStreams`）：`tech`（复活、尸爆、疫医随机职业）与 `skills`（技能触发概率）。命名流互相独立，不会扰动现有 `spawn/boss/promote/hero/jitter/fx`。

- 禁止在 `src/sim/**` 使用 `Math.random()`。
- 新命令必须走 `Sim.applyCommand` 并记录进 `state.commands`：
  - `{ op: 'buyTechNode', nodeId }`

### 6.3 效果聚合

`Tech.mods(state)` 返回预计算对象，直接缓存在 `state.techMods`；每次购买后按固定顺序整体重建（不做增量累加）：

```
{
  dmgMul, atkSpeedMul, hpMul, regenPct, reviveChance, boomChance, boomRadius,
  infectResist, dmgReduction, buildHpMul, buildCapBonus,
  classPassives: { pistol, shotgun, mg, flame, rocket, shield, medic, civilian },
  classActives: { pistol: {id, cd}, ... },
  support: { healCost, bombCost, healUses, bombUses, radiusMul, powerMul },
  hero: { dmgMul, hpMul, officerRange, officerUses, samuraiChain, samuraiPower,
          gatlingHeal, gatlingDuration, plagueCap, plagueChance, plagueRandom,
          medicalRank },
  capstone: { dmgMul, atkSpeedMul, cdMul, lastStand }
}
```

- `bankDamageMul` 不入缓存，直接按 `state.money` 现算（会随花钱变化）。
- `Stats.human()` 是热路径：只做对象字段读取与少量乘法，不分配对象；`state.techMods` 缺失时全部按 1/0 兜底，方便测试直接 `State.create`。
- 每回合按 `state.battle.time` 每 300 步触发一次回血与再生。
- `Tech.buy(state,nodeId)` 流程：校验整备期/节点/前置/等级/金钱 → 记录旧 `techMods` → 扣钱 → 等级 +1 → 固定顺序重算 `techMods` → 按差值补足现有单位/建筑生命与治疗兵血清。返回 `{ok, nodeId, rank, cost, nextCost, reason}`。
- 购买逻辑放 `src/sim/tech.js`，只调用 `Economy.spend`；`Economy` 不再持有科技规则。

### 6.4 状态与回放

```js
state.version = 2;
state.tech = { ranks: { /* 所有节点预置 0，固定形状 */ } };
state.techMods = { /* 派生缓存，不进快照 */ };
state.supports = { uses: { areaHeal: 0, missileBombardment: 0 } };
state.battle.regenT = 5;
state.battle.revives = 0;
state.ui = { showTech, techBranch, techNodeId, pendingSupport };
// human: skillCd, skillUses, skillT, reviveRound, focusTargetId, focusStacks
// zombie: stunT
```

- `Tech.init(state)` 在 `Sim.createGame` 中预置全部节点为 0，保证 `state.tech.ranks` 形状固定；`State.create` 仍创建空壳，直接调用者不会崩。
- `Tech.rebuild(state)` 按**固定 nodeOrder** 从头重算 `techMods`，与购买顺序无关，避免浮点累加顺序影响回放。
- `snapshot()` 只输出非零节点并按 id 排序：`tech: [[nodeId, rank], ...]`；`supports` 同理。`techMods`、`ui.showTech/techBranch/techNodeId/pendingSupport` 不进快照。
- 施放援助的合法性校验**不读 `ui.paused` 或 UI 开关**，只读模拟状态；避免“暂停时能不能放”导致回放分叉。
- 命令回放测试覆盖：买节点（含被拒绝的购买）→ 开战 → 施放援助 → 结算，两次 hash 一致。
- 旧局内状态本来就不持久化，无需迁移；`zd_settings` 与 `SAVE_VERSION = 1` 不变；`state.version` 升到 2 仅用于调试。

### 6.5 关键实现注意

- **主动技能数据结构**：每个拥有主动技的职业/英雄在 data 中有 `active: { id, kind, trigger:'interval'|'attack', cooldown, firstDelay, usesPerRound, condition, params, fx }`；`Skills` 用 `handlers[kind]` 与 `conditions[type]` 两张查表分派，避免 `ai.js` 继续堆 `if (heroId === ...)`。
- **技能钩子**：`AI.stepHumans` 的计时块（`ai.js:909-926`）递减 `skillCd/skillT`；在兵种分派前统一调用一次 `Skills.stepAuto(state,h,dt)`；`performHumanAttack` 成功后调用 `Skills.onAttack`（武士剑气、连射专注等）。原 `stepHeroAbilities` 的三处调用合并为一处。
- **长官导弹**：现有 `abilityUsed` 是每回合一次；改为 `officerUses` 次数，每次导弹流程仍按间隔 0.4s 连发；`stats.missilesFired` 累计。旧的 `nextInspireAt/nextGroupHealAt` 字段由 `skillCd` 取代，测试同步改造。
- **武士剑气**：现为硬编码 25%；改为 `0.25 + samuraiChain` 的触发与连锁逻辑，连锁最多 3 道，每次连锁独立判定。
- **加特林鼓舞**：现每 45s、半径 200、+30% 攻速 8s；强化后增加治疗与时长；治疗走 `Combat.heal`，驱散走 `Infection.dispel`。
- **疫医转化**：`tryConvert` 读取概率/上限；`convertZombie` 读取随机职业；随机使用 `rng.tech`；转化兵仍不占人口、到期消失、不参与晋升。
- **复活**：在 `Combat.killHuman` 最前面、`h.alive = false` 之前判定；排除英雄（走重伤）与队长（走爆炸）；同一单位每回合最多一次（`reviveRound`）。成功则回到 40% 生命、清除感染、不生成 walker、不触发尸爆。
- **尸爆**：在确认死亡后、生成 walker 前判定；复用 `Projectiles.explode` 或直接遍历僵尸，`sourceIsHuman:false`，只伤僵尸；只对非英雄、非队长生效。
- **每回合重置**：`Sim.startRound` 调 `Skills.resetRound(state)`，重置每名人类的 `skillCd/skillUses/skillT/reviveRound`；同时在 `resetRoundBattle` 清零 `supports.uses` 与 `battle.regenT`。
- **建筑数量**：`buildCapBonus` 对每种建筑独立加；已建数量超过新上限时（不会发生，因为只增不减）无需处理。
- **建筑生命**：新建筑乘 `buildingHpMul`；购买节点时按比例补足现有建筑。
- **每 5 秒回血**：只对存活人类，按最大生命百分比；不复活、不驱散。
- **绝境**：`≤3` 名存活人类时全局增益，每步或每帧读取 `state.humans` 存活数即可，注意性能（每 15 步更新一次缓存）。

## 七、平衡方案

新树满配提供约 +30%–50% 战力。为避免“树白送”，同步上调难度，并用 bot 收敛：

| 旋钮 | 现状 | 建议起点 | 说明 |
|---|---|---|---|
| 僵尸 HP 成长 | `1.06^(R-1)` | `1.065^(R-1)` | 主要难度旋钮 |
| BOSS HP 成长 | `1.14^(R-1)` | `1.145^(R-1)` | 四只 BOSS 共用 |
| 僵尸伤害成长 | `1.01^(R-1)` 上限 +50% | 不变 | 避免前期暴毙 |
| 僵尸数量 | `6 + 5R` | 不变 | 保性能与前期体验 |
| 科技总价 | 约 3.5 万（旧 4 线满级） | 约 3.2 万（新树全买） | 后期主要金钱出口；按流派取舍时实际投入更低 |

验收线：

- `node tests/bot.js --rounds 42 --seed 1`：R38–42 通关。
- 多 seed（1–4）：至少 3 个 seed 到 R35+，不出现 R15 前团灭。
- `--rocket-only`：仍应在 R5–R10 失败，证明单一兵种不能通关。
- 若 bot 明显强于 R42：优先上调 HP 成长到 1.07；若明显弱于 R35：下调到 1.062 或降低节点费用。

## 十、风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| `Stats.human` 热路径变慢 | 300 僵尸基准超 2.5ms | `Tech.mods` 缓存；只读字段；`bench` 卡门禁 |
| 新随机破坏确定性 | 回放测试失败 | 统一 `rng.tech / rng.skills`；快照纳入新字段；回放测试覆盖援助 |
| 47 节点 UI 在 1024 宽度拥挤 | 文字截断、误触 | 节点卡简洁 + 详情条；1280 以下自动缩短文案；先选中再购买 |
| 手机横屏被判定为桌面布局 | 体验错误 | 用 `(pointer: coarse)` 或 `Platform.isMobile` 判定，不只靠宽度 |
| 援助瞄准与单位操作冲突 | 误拖拽/误放 | `ui.pendingSupport` 优先拦截；Esc/右键取消；移动端点击确认 |
| 旧测试硬编码四科技 | 大面积红 | 阶段 1 一次性改造 data/economy/view/policy 测试 |
| PWA 缓存旧文件 | 线上看不到新版 | `CACHE` 升到 `zd-v1.4.0` + 新文件进 `SHELL` |
| 新树让 bot 过强/过弱 | 平衡失控 | 只调 HP/BOSS 成长与价格两个旋钮；多 seed 回归 |
| 跳级速通 | 只买每层 1 个节点，约 1,970 金直达 T6 | 监控“首个 T6 回合”；必要时抬高 T5/T6 价格或把终局节点数值控制在 +10% 以内；不改变“任一点解锁”规则 |
| `file://` 加载失败 | 双击不能玩 | 不引入 module/fetch；新脚本全部静态 `<script>` |
| SW 漏列新文件 | 线上白屏/旧代码 | 新增 `tests/shell.test.js` 解析 `index.html` 与 `sw.js`，断言脚本清单一致 |
