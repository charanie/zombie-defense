# 尸潮防线 v1.2 改版实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把现有“部署区站桩 + 固定槽位/出生点 + 火箭兵一家独大”的 v1.1 玩法，改造成“人类小队自主搜索与结阵、僵尸四面来袭、建筑自由摆放且有数量上限、手机端可横屏/竖屏自适应”的 v1.2。

**Architecture:** 保留 1280×720 固定世界、固定步长与零依赖经典脚本架构。新增 `src/sim/squads.js` 作为人类编队的纯模拟模块；`ai.js` 只负责把编队槽位转化为移动与攻击。把 `map.deploy / map.slots / map.spawns` 三个概念从运行时移除，改为“世界边界 + 障碍/建筑碰撞 + 动态流场 + 四边环形出生”。建筑改成带形状与数量上限的自由实体，人类和建筑都不再受部署区约束。视图层改为“画布铺满可用区域、世界等比居中、HUD 全宽 + 安全区 + 可滚动弹窗”，并在首次手势时尝试全屏锁定横屏，失败则竖屏可玩。

**Tech Stack:** 原生 JavaScript（ES5 风格 IIFE）、Canvas 2D、DOM HUD、CSS、Node 内置测试（`node --test`）、无 npm 运行时依赖、无构建步骤。

**Spec:** 本文件 §1「需求与决策基线」（2026-10-19 与用户的澄清记录）；原始玩法真相仍需同步更新到 `docs/game-plan.md`。

## Global Constraints

以下约束来自 `AGENTS.md`，每个任务都隐含适用：

- **运行时零依赖、零构建**：不引入 npm 包、打包器、ES module、外部字体/图片/音频。所有资源本地静态。
- **`file://` 必须可玩**：不能用 ES module / `fetch` 加载游戏代码 / Service Worker 作为必需路径。
- **加载顺序唯一真相**：所有脚本只在 `index.html` 中按顺序声明；测试用 `tests/load-sim.js` 解析它。新增 `src/sim/squads.js` 时必须同时更新 `index.html` 与 `sw.js`。
- **分层**：`src/core` ← `src/data` ← `src/sim` ← `src/view` / `src/main.js`。`src/sim/**`、`src/data/**`、`src/core/**` 不得访问 `document`、`window`、`localStorage`、`Math.random()`、`Date.now()`、`performance.now()`。
- **确定性**：模拟随机一律走 `state.rng.*`；同种子 + 同整备期命令必须得到相同 `ZG.State.hash()`。编队分配必须按 `id` 排序，不得依赖对象遍历顺序。
- **固定步长**：`ZG.Const.STEP_SEC = 1/60`，不得用帧数当时间。
- **数值集中**：单位/僵尸/英雄/建筑/地图/波次/公式只写在 `src/data/**`；`src/sim/**` 不写魔法数字。本计划新增的参数全部进入 `src/data/humans.js` 的 `humanAi`、`src/data/buildings.js`、`src/data/zombies.js`、`src/data/constants.js`。
- **中文文案**：所有玩家可见文字为简体中文；代码标识符用英文。
- **可访问性**：颜色之外有符号/文字/形状；伤害数字与震屏可关；暂停随时可用。
- **验证**：每个任务结束必须运行对应测试；最终必须运行 `npm test`、`node tests/bench.js`、`node tests/bot.js --rounds 40 --seed 1`，并做浏览器手动验收后才能声称完成。

## Review Focus

以下五类输入/条件最容易在实现后“看起来能跑但实际不能玩”，每一条都必须在对应任务里有测试或明确验收步骤：

1. **无敌人时的全图搜索**：所有僵尸清空但还有未出生批次时，人类不能原地发呆、不能在地图边缘来回抖动、不能走回原始放置点；应朝最近的待出生边缘推进并在安全距离停住。
2. **任意位置放置**：人类/建筑放在地图四角、紧贴障碍、紧贴已有建筑时必须给出正确结果；不能出现放进去后卡死、指针坐标偏移、拖拽穿墙。
3. **盾尸拦截的边界**：多个盾尸同时在射线附近、盾尸背对射手、盾尸盾值已破、火箭/药瓶/霰弹多弹丸时，必须只拦截“正面、有盾、最近”的那一只，且火焰不被拦截。
4. **手机宽屏/竖屏/安全区**：20:9 宽屏手机的左右区域、刘海/底部手势条、竖屏降级布局下，设置弹窗最后一项必须能滚动到、所有按钮可点、战场指针坐标不能偏移。
5. **平衡回归**：纯火箭兵阵容不得再稳定打到 R40；混合阵容仍应能通关；建筑上限必须真正阻止“全图堆满哨塔/墙”。

## 3. 设计

### 3.1 人类小队与阵型（Task 6）

#### 3.1.1 概念

- **Squad（小队）**：以一名盾兵为核心，吸收附近最多 6 名非盾战斗单位；多出来的单位进入同一小队的“后续梯队”（tier 1、2…），仍然排在同一条盾线后方，不会各自乱跑。
- **Front line（盾线）**：盾兵在垂直于威胁方向的横排；盾兵数量 >4 时自动排第二排，第二排横向错开半个间距。
- **Slot（阵位）**：每名单位根据职业获得一个相对盾线的横向偏移与纵深；远程/治疗在更后方，喷火/霰弹在中排，近战在盾后第一排。
- **Threat（威胁）**：小队锚点到最近僵尸的方向；没有僵尸时，指向最近的待出生批次边缘；没有待出生批次时指向地图中心。
- **Search（搜索）**：没有僵尸时，盾线仍以小队速度向威胁方向推进，直到距地图边缘 `searchStopInset` 或接敌；不会回到 `homeX/homeY`。

#### 3.1.2 数据结构（新增 `src/sim/squads.js`）

```js
state.squads = [{
  id: 0,                     // 按盾兵 id 升序编号
  shieldIds: [12],           // 核心盾兵
  memberIds: [3, 7, 9],      // 非盾战斗单位（含英雄）
  civilianIds: [5],          // 平民
  tiers: { 3: 0, 7: 0, 9: 1 },
  anchorX: 600, anchorY: 520,
  frontX: 600, frontY: 500,
  faceAngle: -Math.PI / 2,
  targetX: 600, targetY: 120,
  targetZombieId: 0,
  mode: 'search' | 'advance' | 'hold'
}]
```

每名人类新增/复用字段：

```js
h.squadId = 0;
h.squadTier = 0;
h.role = 'rifle' | 'melee' | 'flame' | 'shotgun' | 'mg' | 'rocket' | 'medic' | 'civilian' | 'tank';
h.formationX = 0;
h.formationY = 0;
h.shieldBroken = false;
```

`role` 放在 `src/data/humans.js` / `heroes.js`，由 `State.spawnHuman` 复制；不要用 `attack.kind` 猜。

#### 3.1.3 编队重建

`ZG.Squads.rebuild(state)`：

1. 取所有存活、且 `shieldBroken === false` 的盾兵，按 `id` 升序；每个盾兵一个小队。已经破盾的盾兵按 `role='rifle'` 作为普通成员参与编队，不再当核心。
2. 取所有存活非盾战斗单位（含英雄、不含平民）以及破盾盾兵，按 `id` 升序。
3. 对每个单位，按“到各小队锚点距离升序、距离相同按 id”选择小队：
   - 距离 ≤ `joinRadius`（默认 280）→ 进入该小队；
   - 否则进入最近小队作为后续梯队（仍然归队，不留在原地）。
4. 同一小队内按距离排序，前 `capacity`（6）个为 tier 0，之后每 6 个升一档。
5. 平民单独按最近小队分配，放到该小队 `civilianIds`，纵深额外 +60。
6. 没有盾兵时：创建 1 个无盾小队，所有战斗单位按“近战/喷火在前、远程在后”的虚拟盾线排列；仍使用同一套 slot 逻辑。
7. 重建触发：战斗开始、每 `rebuildSec`（1 秒）、盾兵死亡/破盾/新盾兵出现。为防抖动，若单位原小队仍存在且距离 ≤ `joinRadius * 1.35`，优先保留原小队。

确定性要求：所有数组排序使用 `(a.id - b.id)` 作为最终决胜；不得使用 `state.humans` 的原始顺序作为唯一依据。

#### 3.1.4 每步更新

`ZG.Squads.update(state)` 每个模拟步调用一次：

1. 对每个小队选择目标：
   - 有僵尸：按小队 id 顺序，贪心选择“离本队锚点最近、且未被其他小队选走”的僵尸；都被选走则允许重复选最近的。
   - 无僵尸：从 `state.spawner.batches` 的未出生批次里，选择离锚点最近的出生点；没有则选地图中心 `(640, 360)`。
2. 计算 `faceAngle = atan2(targetY - frontY, targetX - frontX)`。
3. 计算盾线是否推进：
   - 目标是僵尸且距离 > `engageRange`（本队最大射程 + 60）→ `mode='advance'`，`front += dir * squadSpeed * dt`。
   - 目标是搜索点且距离 > `searchStopInset` → `mode='search'`，同样推进；接近边缘时停在距边界 `searchStopInset` 的位置。
   - 否则 `mode='hold'`。
4. 对每个成员计算 `formationX/formationY`（见下）。
5. 盾线位置限制在世界内；如果盾线前方被墙/障碍挡住，尝试沿垂直方向偏移 ±`shieldSpacing`、±2×`shieldSpacing`，选第一个可行点；都不行则保持。

`squadSpeed`：有盾兵时 `min(盾兵 moveSpeed, 58)`；无盾时 `min(队内最快近战 moveSpeed, 58)`。这样后排不会把盾线甩掉。

#### 3.1.5 阵位计算

设 `perp = (-sin(faceAngle), cos(faceAngle))`，`back = (-cos(faceAngle), -sin(faceAngle))`。

- 盾兵：`lateral = (i - (n-1)/2) * shieldSpacing`；`depth = 0`；若 `n > 4`，第二排 `depth = 26`，`lateral += shieldSpacing/2`。
- 其他单位：
  - `baseDepth = roleDepth[h.role]`；
  - `depth = baseDepth + h.squadTier * overflowTierDepth`；
  - 同角色内按 id 排序，`lateral = (j - (m-1)/2) * lateralSpacing`；横向过宽时折成多行，每行最多 8 人，行距 28。
- 平民：`roleDepth.civilian`，并且优先放在小队最后方；如果附近有僵尸且距离 < `civilianFleeRadius`，执行逃跑而不是去阵位。

`roleDepth` 默认值（可在实现时微调，不改结构）：

| role | 纵深 |
|---|---:|
| tank（盾兵） | 0 |
| melee（武士） | 40 |

#### 3.2.2 正面投射物拦截

新增 `ZG.Combat.interceptRay(state, x1, y1, x2, y2, opts)`：

- 输入：射手位置 `(x1,y1)`、原本要打的目标点 `(x2,y2)`、`opts.excludeId`、`opts.pad`。
- 遍历存活盾尸，满足以下全部条件才可作为拦截者：
  1. `z.typeId === 'shield'` 且 `z.shield > 0`；
  2. 盾尸到射线的垂直距离 ≤ `z.radius + pad`，且投影在线段内（`0 < t < 1`）；
  3. 盾尸比原目标更靠近射手（`t` 更小）；
  4. 盾尸面朝射手：`abs(angleDiff(atan2(y1-z.y, x1-z.x), z.facing)) <= interceptFacingHalfAngle`；
  5. 不是原目标本身（`z.id !== opts.excludeId`）。
- 返回沿射线 `t` 最小的盾尸；没有则返回 `null`。

#### 3.3.2 盾尸伤害管线

`Combat.resolveShield` 对 `target.kind === 'zombie' && target.typeId === 'shield'` 单独处理：

| 伤害类型 | 条件 | 结算 |
|---|---|---|
| 非火焰（远程/爆炸/正面近战 >40） | 盾值 >0、正面 120° | 总伤害 ×0.5，先扣盾、溢出扣血 |
| 火焰（喷火锥/灼烧） | 盾值 >0、正面 120° | 对盾按 2× 消耗；溢出部分按 1× 扣血 |
| 近战 <40 | 任何 | 绕过盾，100% 扣血 |
| 背后来袭 | 角度超出正面 120° | 100% 扣血 |
| 盾值已破 | 任何 | 100% 扣血，并保留破盾减速 20% |

火焰结算公式（避免“2× 溢出”歧义）：

```
shieldCost = amount * 2
if (shield >= shieldCost) { shieldDamage = shieldCost; hpDamage = 0; }
else { shieldDamage = shield; hpDamage = amount - shield / 2; }
```

- 盾尸的 `shieldReduction` 字段废弃，改为 `shieldDamageMul: 0.5`、`fireShieldMul: 2`、`fireBodyMul: 1`。

#### 3.3.5 爆尸爆炸的盾兵守护

新增 `ZG.Combat.shieldGuardMul(state, h, ex, ey)`：

1. 遍历存活盾兵 `s`：
   - `s.classId === 'shield'`、`s.shield > 0`；
   - `dist(s, ex, ey) <= guardMaxDist`（默认 220）；
   - 盾兵面朝爆心：`abs(angleDiff(atan2(ey-s.y, ex-s.x), s.facing)) <= 75°`；
   - 队友在盾后：`dist(s,h) <= guardRadius`（180）；
   - 队友方向与盾兵背后方向夹角 ≤ `guardHalfAngle`（60°）：`abs(angleDiff(atan2(h.y-s.y, h.x-s.x), s.facing + PI)) <= 60°`；
   - 盾兵确实挡在爆心与队友之间：`dist(ex,s) < dist(ex,h)`。
2. 任意一个盾兵满足 → 返回 `0.5`；否则 `1`。多盾不叠加（取最小）。
3. 只有 `kind === 'boomer'` 的爆炸调用；盾兵自身不减免；感染的结算保持原样（只减伤害）。

`Projectiles.explode` 的人类分支：

```js
let dmg = damage;
if (o.kind === 'boomer' && h.classId !== 'shield') {
  dmg *= ZG.Combat.shieldGuardMul(state, h, x, y);
}
```

- 交互：
  - 键盘 `R` 在墙建造模式下切换横/竖；

#### 3.5.3 自由建造/拆除

- `State.spawnBuilding(state, typeId, x, y, opts)`：

#### 3.6.3 横屏请求与竖屏降级

浏览器限制：网页不能在无用户手势时静默旋转系统屏幕；`screen.orientation.lock('landscape')` 需要全屏且多数浏览器只在用户手势后允许。因此实现为：

- `ZG.Platform.orientationPlan({ isMobile, isStandalone, portrait, supportsLock, fullscreenEnabled })` 返回：
  - `'lock'`：移动端 + 竖屏 + 支持锁定时，首次手势后尝试全屏 + `lock('landscape')`；
  - `'portrait'`：其他情况，使用自适应竖屏布局；
  - `'landscape'`：已经是横屏。
- `ZG.Platform.requestLandscape()`：
  - 调用 `document.documentElement.requestFullscreen()`；
  - 成功后 `screen.orientation.lock('landscape').catch(...)`；
  - 失败/不支持则保持竖屏布局，并 toast“浏览器不支持自动横屏，已切换竖屏布局”。
- 首次手势：在 `main.js` 的首次 `pointerdown`（或地图卡点击）调用一次 `requestLandscape()`；不要每次点击都弹。
- 删除全屏“请横屏游玩”遮罩；改为竖屏时显示一个可关闭的提示条：
  - “建议横屏 · 点此全屏”按钮；
  - 用户关闭后不再显示；
  - 设置里保留“全屏 / 横屏”按钮。
- `manifest.webmanifest` 的 `orientation: "landscape"` 保留（安装版 PWA 生效）。
- 横屏后如果用户退出全屏/旋转回竖屏，重新布局为竖屏可玩，不阻断。

#### 3.6.4 截图问题的具体修复

截图暴露的三个问题：

1. **左右黑边**：`#stage` 被 `width: min(100vw, 100vh*16/9)` 限制；改为全宽 stage + 世界居中 + 背景填充。
2. **设置列表被截断**：`.settings-box` 没有 `max-height/overflow`；加上滚动后“分享游戏/全屏”可见。
3. **按钮点不到**：弹窗溢出 + 触控目标过小；修复滚动、safe-area、44px 最小尺寸。
4. **竖屏完全不能玩**：删除阻断遮罩，改为竖屏自适应 + 可选全屏横屏。

## 7. 风险与回滚

| 风险 | 表现 | 缓解 |
|---|---|---|
| 阵位抖动/来回走 | 单位在阵位附近左右摇摆 | `arriveEps=8`；阵位分配按 id 稳定；保留原小队；移动向量加阻尼；测试 300 步哈希与位置 |
| 后排追不上盾线 | 远程/治疗落在最后 | `squadSpeed` 取盾兵速度；slot 在盾后；单位移动速度高于盾兵，能追上 |
| 全图搜索走太远 | 人类跑到边缘被四面夹击 | 搜索点距边界 `searchStopInset=120`；接敌立即回阵；玩家可用多盾分散布置 |
| 流场重建太频繁 | 性能下降 | 15 步一次；建造/摧毁才立即重建；bench 监控 |
| 自由建墙围死 | 僵尸/人类卡死 | 墙上限 10；流场不可达格；8 秒传送兜底；不允许多建筑重叠 |
| 盾尸拦截过强 | 远程完全打不到后排 | 只有正面/有盾/最近的盾尸拦截；火焰/近战绕过；破盾后失效；侧翼可打 |
| 火箭削弱过度 | 后期打不动巨人/BOSS | 直击仍 100% + 攻城 1.25；溅射 50% 清群仍有效；bot 验证 |
| iOS 无法锁定横屏 | 仍竖屏 | 竖屏自适应可玩；提示条 + 全屏按钮；不阻断 |

```text
rebuild(state):
  shields = alive humans where classId == 'shield' sorted by id
  combat  = alive humans where classId not in ('shield','civilian') sorted by id
  squads = shields.map((s,i) => new Squad(i, s))
  if squads empty: squads = [new Squad(0, null)]

  for h in combat:
    best = squads
      .filter(s => dist(h, s.anchor) <= joinRadius && capacityLeft(s) > 0)
      .sort(by dist, then s.id)[0]
      or squads.sort(by dist, then s.id)[0]
    assign h to best, tier = floor(indexWithinSquad / capacity)

  for c in civilians:
    assign to nearest squad as civilian

  each squad: anchor = centroid(shields) or centroid(members)
  return squads
```

### B.2 小队更新

```text
update(state):
  used = set()
  for squad in state.squads:
    if any zombie:
      target = nearest zombie to squad.anchor not in used; else nearest
      used.add(target.id)
    else:
      target = nearest pending spawn point to squad.anchor
      if none: target = map center
    face = atan2(target - front)
    if target is zombie and dist(front,target) > engageRange:
      front += dir(face) * squadSpeed * dt
    else if target is search point and dist > searchStopInset:
      front += dir(face) * squadSpeed * dt
    clamp front to world with margin
  for h in all humans:
    slot = slotFor(state,h)
```

### B.3 投射物拦截

```text
interceptRay(state, x1,y1, x2,y2, opts):
  best = null; bestT = 1
  for z in state.zombies:
    if not alive or z.typeId != 'shield' or z.shield <= 0: continue
    if z.id == opts.excludeId: continue
    t = segmentCircleT(x1,y1,x2,y2, z.x,z.y, z.radius + (opts.pad||6))
    if t == null or t <= 0 or t >= bestT: continue
    if abs(angleDiff(atan2(y1-z.y, x1-z.x), z.facing)) > interceptFacingHalfAngle: continue
    best = z; bestT = t
  return best
```

### B.4 火箭爆炸

```text
explode(x,y,radius,damage,kind,opts):
  directId = opts.directTargetId
  if directId not alive/near: directId = nearest zombie within radius
  for z in zombies within radius:
    dmg = (z.id == directId) ? damage * (z.isSiege ? siegeBonus : 1)
                             : damage * (opts.splashMul || 1)
    applyDamage(z, dmg)
```

### B.5 爆尸守护

```text
shieldGuardMul(state, h, ex, ey):
  for s in humans:
    if s.classId != 'shield' or not alive or s.shield <= 0: continue
    if dist(s,ex,ey) > 220: continue
    if abs(angleDiff(atan2(ey-s.y,ex-s.x), s.facing)) > 75°: continue
    if dist(s,h) > 180: continue
    if abs(angleDiff(atan2(h.y-s.y,h.x-s.x), s.facing + PI)) > 60°: continue
    if dist(ex,s) >= dist(ex,h): continue
    return 0.5
  return 1
```
