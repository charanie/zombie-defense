> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 按 `docs/superpowers/plans/2026-10-22-v1.4-tech-tree-rework.md` 把四条线性科技替换为 4 分支 × 6 层 × 47 节点的单局科技树，并接入职业被动/主动、英雄强化、场外援助与新科技大窗口。

## 1. Global Constraints

以下约束每个任务都生效：

- **零依赖、零构建**：运行时只有 `index.html + src/**/*.js + styles.css + sw.js + icons/`；不用 npm 包、打包器、ES module。
- **`file://` 可玩**：所有代码通过经典 `<script>` 加载；不得用 `fetch` 加载游戏代码；不得把 Service Worker 作为必需路径。
- **加载顺序唯一真相**：新增脚本只写进 `index.html`；`tests/load-sim.js` 会自动按它加载。
- **分层**：`core ← data ← sim ← view/main`。`src/sim/**`、`src/data/**`、`src/core/**` 禁止 `document`、`window`、`localStorage`、`Math.random()`、`Date.now()`、`performance.now()`。
- **固定步长**：`ZG.Const.STEP_SEC = 1/60`，禁止用帧数计时。
- **确定性**：模拟随机只走 `state.rng.*`；同种子 + 同命令必须同 `ZG.State.hash()`。
- **数值集中**：节点数值、技能冷却、援助参数只写在 `src/data/tech.js`；`src/sim/**` 不写魔法数字。`Balance` 只放纯公式。
- **中文文案**：玩家可见文字为简体中文；代码标识符英文。
- **版本**：`ZG.Const.VERSION = 'v1.4.0'`；`package.json version = '1.4.0'`；`sw.js CACHE = 'zd-v1.4.0'`（Task 8 统一改，之前不改）。
- **状态版本**：`state.version = 2`（Task 2 改）。
- **性能预算**：`node tests/bench.js` 的 `avgStepMs ≤ 2.5`。
- **可访问性**：科技节点状态用颜色 + 图标 + 文字三重表达；触控目标 ≥ 44px；`role="dialog" aria-modal="true"`。

## 2. 裁决表

计划书内部有少量不一致或未落到接口的地方，本文固定如下：

| # | 问题 | 裁决 |
|---|---|---|
| 1 | 节点价格写 `floor(base×1.35^n)`，示例却是 219/398 | 用 `Math.round`：120 / 162 / 219 / 295 / 398；否则第 3 级为 218，与示例不符 |
| 2 | 长官导弹改为多次后如何避免一回合内连放 | 每次齐射后 `skillCd = 8` 秒；齐射仍是 3/5 发、每发间隔 0.4s |
| 3 | 盾兵主动“嘲讽 220 半径 2 秒”没有现成机制 | 施放时给范围内僵尸写 `tauntT=2, tauntTargetId`；`pickZombieTarget` 优先返回该人类；僵尸死亡/目标消失自动失效 |
| 4 | 轰炸“2 发间隔 0.15s”的落点 | 固定偏移：第 1 发 `(x-24, y-12)`，第 2 发 `(x+24, y+12)`；不取随机，保证回放 |
| 5 | 悬浮技“12 段 ×8”如何计时 | 施放时 `skillT=1, skillTickN=12, skillTickT=0`；每 `1/12s` 对 150 半径内僵尸结算 8 点，共 12 次 |
| 6 | `lastStand` 随存活人数变化 | `Tech.updateDynamic(state)` 每 15 步更新 `techMods.lastStandActive`，不参与购买时的整体重算 |
| 7 | BOSS 对眩晕/击退的抗性 | BOSS 免疫眩晕（不写 `stunT`）；`knockbackImmune` 的僵尸免疫击退，其余可被推开 40 |
| 8 | 复活与尸爆的先后 | 先判复活；复活成功则本次死亡完全取消（不爆炸、不生成 walker）；失败才判尸爆，再走原死亡链 |
| 9 | 英雄 / 队长是否吃复活、尸爆 | 都不吃；英雄走重伤，队长走死亡爆炸 |
| 10 | 购买生命节点时“补足现有单位” | 按购买前后 `hpMul / hero.hpMul / shieldMul / buildHpMul` 的比值缩放；跳过 `!alive`；比值 1 时不做任何浮点运算 |
| 11 | 存款加伤缓存 | 不入 `techMods`；`Stats.human` 每次用 `state.money` 现算 |
| 12 | `medical_system` 是否给疫医血清 | 不给。只给治疗兵 `serumLeft +1/级`；疫医的单体/群体治疗量 +8%/级 |
| 13 | 职业主动技的冷却缩减 | `cap_cd` 的 `skillCdMul = 0.85` 只乘在“主动技冷却”和长官齐射间隔上，不乘 `serumCd/dispelCd` |
| 14 | 科技购买入口 | 仅 `state.status === 'prep'`；面板打开时 `state.ui.showTech = true`，该字段不进快照 |
| 15 | 节点价格展示 | `nodeView.cost` 是“下一级价格”；满级为 `null` |
| 16 | 旧存档 | 不迁移；`zd_settings` / `SAVE_VERSION` 不变；单局状态本来就不持久化 |

## 3. Review Focus

实现时最容易踩坏、且计划书不会逐条测试的五类输入：

1. **购买生命节点时的缩放**：对已受伤、英雄、带盾、已死亡单位各缩放一次，不能重复乘、不能给 `!alive` 单位改 HP。→ Task 3 的 `购买生命节点按比值补足` 测试。
2. **复活 / 尸爆 / 转化三者叠加**：复活成功不得再生成 walker；队长与英雄不得触发复活或尸爆；同一单位每回合只能复活一次。→ Task 4 的 `复活每回合一次`、`英雄队长不复活` 测试。
3. **援助瞄准的残留状态**：战斗结束、暂停、点地图外、重复点按钮、Esc/右键取消后，`pendingSupport` 必须清空且不扣钱。→ Task 6 的 `援助命令校验` 与浏览器验收。
4. **新随机流被无谓消耗**：概率为 0 / 节点未购买时不得调用 `rng.tech.chance`，否则同种子回放分叉。→ Task 4 的 `未购买时不消耗随机流` 测试。
5. **`Stats.human` 热路径**：每发子弹调用一次，不得分配对象、不得遍历 47 节点、不得扫描建筑以外的集合。→ Task 3 的实现约束与 Task 8 的 `bench` 门禁。

效果描述符 `effects` 支持 9 种 `type`：

| type | 字段 | `Tech.rebuild` 行为 |
|---|---|---|
| `scalar` | `key, perRank` 或 `value` | `mods[key] += perRank * rank`（`mods[key]` 初始为 1 或 0） |
| `table` | `key, values` | `mods[key] = values[rank]` |
| `flag` | `key` | `mods[key] = true` |
| `econ` | `killPerRank, rewardPerRank` | `mods.econKillMul += killPerRank*rank`；`mods.econRewardMul += rewardPerRank*rank` |
| `bank` | `per500, capByRank` | `mods.bankPer500 = per500`；`mods.bankCap = capByRank[rank-1]`；`mods.bankActive = true` |
| `classPassive` | `classId, params` | `mods.classPassives[classId] = params` |
| `classActive` | `classId, params` | `mods.classActives[classId] = params` |
| `hero` | `key, value` 或 `key, perRank` | `mods.hero[key] = value` / `+= perRank*rank` |
| `support` | `key, value` 或 `skill, unlocked` | 写入 `mods.support`；`usesBonus` 同时给 `healUses/bombUses` 加值 |
